# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with the MOSAIC data repository.

## Data Repository Structure

This repository serves as the centralized data storage for the MOSAIC cholera transmission modeling framework. It contains both raw and processed data used by the MOSAIC R package.

## Directory Organization

### `raw/` (READ-ONLY)
- Contains original, unprocessed data files
- **DO NOT MODIFY** - This directory is local only and should not be edited
- Sources: APIs, manual downloads, external databases

### `processed/`
- Contains cleaned and processed data files ready for analysis
- Generated by MOSAIC-pkg functions
- Organized by data type and source

## Data Categories

### Climate Data (`processed/climate/`)
- Historical and forecast climate data by country
- Sources: OpenMeteo API, MRI-AGCM3 climate models
- Formats: `.csv`, `.parquet` files
- Aggregations: daily, weekly, monthly

### Cholera Surveillance (`processed/cholera/`, `processed/WHO/`)
- WHO weekly surveillance data
- Annual cholera reports
- Case and death counts by country and time
- Formats: `.csv` files

### Demographics (`processed/demographics/`)
- UN World Population Prospects data
- Population, birth rates, death rates by country
- Age structure and demographic projections
- Formats: `.csv` files

### Environmental Data
- **DEM** (`processed/DEM/`): Digital elevation models by country
- **ENSO** (`processed/ENSO/`): El Niño Southern Oscillation indices
- **WASH** (`processed/WASH/`): Water, sanitation, and hygiene coverage data

### Mobility Data (`processed/OAG/`)
- Flight connectivity data
- Origin-destination matrices
- Processed from OAG (Official Airline Guide) data
- Formats: `.csv` files


### 3. Processed Data Storage
- Results saved to appropriate `processed/` subdirectories
- Standardized formats and naming conventions
- Ready for consumption by modeling functions

## File Naming Conventions

### Climate Data
- `climate_data_[ISO]_[frequency].parquet`
- `climate_data_[model]_[dates]_[ISO].parquet`

### Cholera Data
- `cholera_country_weekly.csv`
- `who_afro_annual_[years].csv`

### Demographics
- `demographics_[region]_[years].csv`

### Country-specific Data
- Files prefixed with 3-letter ISO country codes
- Examples: `AGO_`, `NGA_`, `MOZ_`

## Data Quality Standards

### Required Fields
- **Country identification**: ISO 3-letter codes
- **Temporal information**: Standardized date formats (YYYY-MM-DD)
- **Spatial information**: Consistent geographic boundaries

### Data Validation
- Processed data includes validation checks
- Missing data handling documented
- Outlier detection and treatment applied

## Access Patterns

### Read Access
- MOSAIC-pkg functions read from `processed/` directory
- External tools can read processed data for analysis
- Documentation references processed data for figures

### Write Access
- Only MOSAIC-pkg processing functions should write to `processed/`
- Raw data directory is read-only
- Processed data can be regenerated from raw data

## Integration with Other Repositories

### MOSAIC-pkg Integration
- Path management via `get_paths()` function
- Processing functions write to appropriate subdirectories
- Data validation and quality checks integrated

### MOSAIC-docs Integration
- Processed data used for documentation figures
- Summary statistics and tables generated from processed data
- Data availability and coverage documented

## Common Data Operations

### Loading Data
```r
# Standard pattern for loading processed data
file_path <- file.path(PATHS$DATA_PROCESSED, "climate", "climate_data_MOZ_weekly.parquet")
climate_data <- arrow::read_parquet(file_path)
```

### Data Aggregation
- Country-level aggregations from point data
- Temporal aggregations (daily → weekly → monthly)
- Spatial aggregations using geographic boundaries

### Data Joining
- Country-level joins using ISO codes
- Temporal joins using standardized date formats
- Spatial joins using geographic identifiers

## Backup and Version Control

### Version Control
- Processed data tracked in git repository
- Raw data kept local only (not in version control)
- Large files may use Git LFS if needed

### Data Lineage
- Processing functions document data sources
- Transformation steps logged and documented
- Reproducible pipeline from raw to processed data
